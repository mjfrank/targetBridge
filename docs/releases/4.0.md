# TargetBridge 4.0

TargetBridge 4.0 adds uncompressed video modes that send only what changes on
screen, optionally in 10-bit colour over parallel connections, with one-click
5K stream profiles for them. It also adds a per-session audio output device, a
version check between Sender and Receiver, a quieter, more configurable
Receiver, and a Receiver for older Intel Macs down to macOS 10.14 Mojave.

> The version number is this fork's proposal. Whether these changes ship as
> 4.0 upstream is up to the original maintainer.

## Highlights

### Uncompressed video

The video compression setting now offers four uncompressed options next to
Automatic, H.264 and HEVC. All of them skip the video codec, so the picture
arrives without compression artefacts, and all of them send only the rows of
the screen that changed: a still desktop costs almost no bandwidth.

| Option | Captured | Sent and shown | Frame rate at 5K |
|---|---|---|---|
| Uncompressed (8-bit) | 8-bit 4:2:0 | 8-bit 4:2:0 | 60 Hz |
| Uncompressed, LZ4, lossless (8-bit) | 8-bit 4:2:0 | 8-bit 4:2:0, compressed losslessly | 60 Hz |
| Uncompressed, enhanced (10-bit dithered, experimental) | 10-bit | 8-bit 4:2:0 with dithering | 60 Hz |
| Uncompressed, full colour (10-bit, experimental) | 10-bit | 10-bit RGB 4:4:4 | about 30 fps for video and scrolling |

- **Changed rows only.** The Sender reads ScreenCaptureKit's dirty rectangles
  and sends only the affected rows. Rows from frames skipped by the frame-rate
  limit or a busy link are kept and sent with the next frame. The first frame,
  size changes and one frame every 5 seconds are sent in full.
- **Lossless LZ4.** Changed rows are compressed in parallel chunks on the
  Sender and decompressed in parallel on the Receiver. The picture stays
  bit-identical.
- **10-bit dithered.** Captured in 10-bit, displayed in 8-bit: a GPU shader
  converts only the rows to send to 8-bit 4:2:0 with an ordered 4×4 dither
  pattern, so gradients stay smooth at the 8-bit bandwidth and flat areas
  still compress well with LZ4.
- **Full 10-bit colour.** The captured 10-bit pixels are sent unchanged at
  4 bytes per pixel and full colour resolution, compressed with LZ4 while
  that pays off (desktop content), raw for video. The Receiver shows them in true 10-bit: a 10-bit drawable and
  texture, filled by a GPU copy of the changed rows without CPU conversion.
- **Parallel data streams.** All uncompressed modes can open up to 4 extra
  connections and spread each frame across them (session setting *Parallel
  connections*, on by default). The Receiver keeps rows in the right order
  even when parts arrive out of order, and draws a frame only once all of its
  parts have arrived.
- **Own Metal video renderer.** The Receiver now draws all video, H.264/HEVC
  and every uncompressed mode, with its own Metal code by default, like
  DisplayBridge. This fixes the flashing of SDL's Metal mode and is what
  shows full 10-bit colour. SDL Metal and SDL OpenGL remain available under
  Performance > Renderer (Expert Settings), along with waiting for the display refresh.
- **Faster drawing.** The Receiver uploads only the changed rows to the
  graphics card.

- **One-click 5K profiles.** Four stream profiles pick both 5K at 60 Hz and the
  matching mode: *5K 60 Uncompressed (8-bit)*, *5K 60 LZ4, lossless (8-bit)*,
  *5K 60 10-bit dithered* and *5K 60 Full 10-bit*. While one of them is
  selected, the video compression setting offers only the uncompressed
  modes, so you can still switch between them within the profile.
  Automation accepts them as `5k60raw`, `5k60lz4`, `5k60dither` and
  `5k60full10`.

Each new capability falls back on its own: an older Receiver gets full frames,
a Receiver without LZ4 gets uncompressed rows, and without a usable GPU or
10-bit support the Sender uses the next simpler mode. See
[Performance](../Performance.md) for details and the wire format.

### Sign-in screen mode (experimental)

The iMac can be used as a display while it shows the sign-in window, with
nobody logged in. Install and uninstall it from the Receiver's menu bar icon;
nothing is installed by default. Esc or a double-click on the iMac ends the
session and gives the sign-in window back; the iMac's keyboard and mouse
never control the Mac in this mode. With FileVault it works after logging
out, not right after a restart. See [Sign-in screen mode](../SignIn-Screen-Mode.md).

### Three Receivers, including older Intel Macs

Releases and CI builds now provide three Receivers, named by processor and
the lowest macOS version they run on:

| File | Processor | Runs on |
|---|---|---|
| `TargetBridge-Receiver-AppleSilicon-macOS15-Sequoia-and-later.app.zip` | Apple Silicon | macOS 15 Sequoia or later |
| `TargetBridge-Receiver-Intel-macOS15-Sequoia-and-later.app.zip` | Intel | macOS 15 Sequoia or later |
| `TargetBridge-Receiver-Intel-macOS10.14-Mojave-and-later.app.zip` | Intel | macOS 10.14 Mojave or later |

- **New: Intel Receiver for macOS 10.14 Mojave or later.** Previous Receivers
  needed the macOS version of the build machine, recently macOS 15 Sequoia,
  because Homebrew's SDL2 and FFmpeg are built for it. This Receiver bundles
  SDL2 2.30.9 and a minimal FFmpeg 7.1 (H.264/HEVC with VideoToolbox hardware
  decoding) built from source for macOS 10.14 Mojave
  ([`build_legacy_deps.sh`](../../TargetBridge-Receiver/scripts/build_legacy_deps.sh)).
  It suits iMacs that can't update to macOS 15 Sequoia, for example the iMac
  (Retina 5K, 27-inch, 2017) on macOS 13 Ventura. Addresses
  [#167](https://github.com/swellweb/targetBridge/issues/167).
- All three have the same features. Two fallbacks apply only before macOS 11
  Big Sur: the Input Monitoring check runs from macOS 10.15 Catalina on (the
  permission doesn't exist before), and the menu bar icon is drawn instead of
  using a system symbol.
- Each build fails if the code uses a newer macOS API without a fallback, or
  if any bundled part needs a newer macOS than the file name says.
- The Receiver downloads were previously named `TargetBridge-Receiver-arm64`
  and `TargetBridge-Receiver-x86_64`.

### Connecting

- **Connect automatically** now connects when the receiver appears: when the
  cable is plugged in, the receiver starts or the Sender opens, like plugging
  in a display. A session that ends stays ended.
- New **Keep alive** option (off by default): reconnects every few seconds
  after the connection is lost, but not after Stop and not after the session
  was ended on the receiver.

### Version check

Sender and Receiver now tell each other their version. If they differ, the
Sender shows a notice with a **Download update** button, and the Receiver shows
it at the bottom of the picture for 20 seconds and in its menu bar, with a
download item, until the session ends. Both name the app that should be
updated. A Receiver older than 4.0 doesn't report a version and is treated as
older.

### Audio

- **TargetBridge Audio output device.** Select it as a per-session audio
  source; it only appears in macOS while a session is running.
- The Mac's volume for this device drives the iMac's speaker volume, and the
  iMac returns to its previous volume when a session ends.
- Per-session automatic audio output selection, returning to the previous
  output after a session, with the built-in output as fallback.
- The audio device can be renamed in Settings > Audio. If the driver needs a
  restart, the Sender shows the `sudo killall coreaudiod` hint.

### Receiver

- **App mode**: Standard (window and Dock icon), Background (menu bar icon
  only, no Dock icon) or Faceless (no window or icons), chosen in the
  window's bottom bar or the menu bar icon. Opening the app again shows the
  window in every mode. "Always show this window at start" works in every
  mode.
- New bottom bar with the Receiver's checkboxes beside the version and the
  Login Items hint; the upside-down waiting screen is fixed.
- **Performance** submenu: draw only the newest frame, wake on incoming data,
  a stats overlay with frame rate, skipped frames, draw time, data rate and
  the share of changed rows, and Renderer (Expert Settings) for developers
  (renderer, display refresh waiting).

### Sender

- **App mode** in Settings: Standard (window and Dock icon), Background (menu
  bar icon only) or Faceless (no window or icons). In Background and
  Faceless the Sender starts without a window; opening it again from the
  Applications folder shows the window.
- Default language follows the system, with an English fallback.
- Session names are editable, sessions can connect automatically, and session
  settings open in a regular window.
- The macOS display is named after the session.
- Brightness Keys and Audio Device add-ons.

## Upgrade

Update both Sender and Receiver to 4.0. The new uncompressed modes need the
4.0 Receiver; with an older Receiver the Sender falls back to full raw frames
or to Automatic. All protocol additions are optional fields and new packet
types, so 3.x Receivers keep working with the established codec modes.

For comparisons on real hardware, start the Sender with `RAW_REGIONS=0` to
send full frames again in the uncompressed modes.

### Keeping privacy permissions across updates

macOS ties Screen Recording, Accessibility and Input Monitoring to the app's
code signature. The builds are signed ad-hoc, which gives every build a new
identity, so macOS asks again after each update. The new
[`scripts/sign-local.sh`](../../scripts/sign-local.sh) signs all downloads in
its folder in one go (Sender and Receiver, Apple silicon and Intel) with your
own certificate, lists which app belongs on which Mac and offers to install
the ones for this Mac. Copy the others to your other Macs; they don't need
the certificate. After one last approval, later updates keep the permissions.
See [Sender signing](../Sender-Signing.md#keep-permissions-on-your-own-macs-sign-after-installing)
for every step.

## Validation

CI builds the Sender for Apple Silicon and Intel and the three Receivers, and
runs the Sender unit tests and the Receiver parser, input-queue, watchdog,
profile, raw-region and version tests, including out-of-order parts and
malformed packets.

Tested on real Mac-to-iMac Thunderbolt setups:
- The 8-bit uncompressed modes, including LZ4, at 5K and 60 Hz.
- 10-bit dithered: video at about 30 fps and 1,700 Mbit/s, moving windows at
  50 fps or more and about 4,000 Mbit/s, without skipped frames.
- Full 10-bit with the TargetBridge Metal renderer: video at 29 to 31 fps and
  about 9,400 Mbit/s.
- The sign-in screen mode.
- The Intel Receiver for macOS 10.14 Mojave or later, on macOS 13 Ventura
  (13.7.8). A test on macOS 10.14 Mojave itself is still open.

## Known Limitations

- ScreenCaptureKit does not document whether dirty rectangles are in points or
  pixels. Ambiguous rectangles are sent in both readings, which can cost some
  extra bandwidth; any stale area is repaired by the full frame every
  5 seconds.
- Full 10-bit colour needs the default TargetBridge Metal renderer; with an
  SDL renderer the Sender uses the dithered mode.
- Full 10-bit colour reaches about 30 fps for video at 5K: 5K at 4 bytes per
  pixel and 60 Hz would need about 28 Gbit/s.
- Uncompressed modes are not available for headless mirror sessions, which
  capture through a different path.
